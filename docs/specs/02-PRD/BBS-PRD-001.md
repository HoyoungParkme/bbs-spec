# PRD: 동아리 게시판

## 1. 목표

#### G1 공지가 묻히지 않는다

운영자가 올린 공지는 내려갈 때까지 목록 맨 위에 있다. 근거: [[BBS-RFQ-001#Q1]]

#### G2 단톡방에서 하던 일이 게시판에서 된다

참석 의사·후기·장비 공구를 글과 댓글로 옮긴다. 근거: [[BBS-RFQ-001#Q3]]

#### G3 브라우저 주소 하나로 끝난다

설치가 없다. 오십 대 회원이 링크를 눌러 바로 읽는다.

## 2. 비목표

| 비목표 | 이유 |
|---|---|
| 모바일 앱 | 회원 40명에 설치를 요구할 이유가 없다. 반응형 웹으로 충분하다 |
| 실시간 알림(푸시) | 단톡방이 이미 있다. 게시판은 **묻히지 않게 쌓는 곳**이지 알리는 곳이 아니다 |
| 글 서식 편집기 | 줄바꿈과 링크면 된다. 에디터를 붙이면 오십 대 회원이 못 쓴다 |
| 여러 게시판(카테고리) | 동아리 하나에 게시판 하나. 나눌 만큼 글이 많지 않다 |

## 3. 요구사항

### 3.1 기능

#### R1 글 목록

최신 글이 위. **공지는 그 위에 따로 묶여 고정된다.** 한 화면에 20개, 그 아래로 페이지 이동. 근거: [[BBS-RFQ-001#Q1]]

- [ ] 공지 묶음과 일반 묶음이 시각적으로 갈린다
- [ ] 각 행에 제목·글쓴이·작성일·댓글 수가 보인다
- [ ] 로그인하지 않아도 목록이 보인다

#### R2 글 쓰기

회원만 쓴다. 제목과 본문, 그리고 운영자면 **공지로 올림** 선택. 근거: [[BBS-RFQ-001#Q2]]

- [ ] 비회원이 글쓰기를 누르면 로그인 화면으로 간다
- [ ] 공지 선택은 운영자에게만 보인다
- [ ] 제목 100자, 본문 10000자를 넘으면 저장하지 않고 알린다

#### R3 글 읽기와 고치기

글쓴이 본인과 운영자만 고치고 지운다. 고친 글에는 **고침 표시**가 남는다.

- [ ] 남의 글의 고치기·지우기 버튼은 아예 안 보인다
- [ ] 고친 글은 목록과 본문에 `(수정됨)`이 붙는다

#### R4 댓글

글 아래에 시간순. 답글은 한 단계까지. 근거: [[BBS-RFQ-001#Q3]] · [[BBS-UC-001#UC-H4]]

- [ ] 회원만 단다
- [ ] 본인과 운영자만 지운다
- [ ] 답글의 답글은 안 된다

#### R5 제목 검색

제목에 포함된 말로 찾는다. 본문은 안 찾는다. 근거: [[BBS-RFQ-001#Q4]]

- [ ] 두 글자 이상부터 찾는다
- [ ] 결과가 없으면 "찾는 글이 없습니다"를 보여준다

#### R6 신고

회원이 글·댓글을 신고하면 운영자 화면에 쌓인다. 근거: [[BBS-RFQ-001#Q5]]

- [ ] 같은 글을 같은 사람이 두 번 신고하지 못한다
- [ ] 운영자가 신고를 보고 **숨김** 또는 **무시**를 고른다
- [ ] 숨긴 글은 목록에서 빠지고 운영자만 본다

### 3.2 비기능

#### N1 목록이 1초 안에 뜬다

회원 40명, 글 5000건 기준. 모바일 LTE에서 잰다.

- [ ] 목록 첫 화면 1초 이내

#### N2 읽기는 로그인이 필요 없다

동아리 홍보가 되는 것이 요구였다. 근거: [[BBS-RFQ-001#Q2]]

- [ ] 비로그인 상태로 목록·본문·댓글을 읽을 수 있다

## 4. 성공지표

| 지표 | 목표 | 어떻게 재나 |
|---|---|---|
| 산행 공지를 게시판에서 본 회원 비율 | 8할 | 공지 글 조회수 ÷ 회원 수 |
| 단톡방 공지 재게시 횟수 | 월 1회 이하 | 운영자가 센다 |
| 광고 글 노출 시간 | 24시간 이내 숨김 | 신고 시각 ↔ 숨김 시각 |

## 5. 미결사항

- [ ] 사진 첨부 — 후기에는 사진이 많다. 용량과 보관 비용을 정해야 한다
- [ ] 회원 가입 승인 방식 — 운영자 승인인지 초대 링크인지
